# LUNA FLOWERS

Премиальный интернет-магазин цветов с современным адаптивным интерфейсом, каталогом букетов, конструктором букетов, системой заказов, административной частью и автоматизацией бизнес-процессов.

* **TanStack Router**
* **SSR**
* **Nitro**
* **Neon PostgreSQL**
* **n8n**
* **Git / GitHub**
* **npm**
* **Cursor**

## База данных

В качестве основной базы данных используется **Neon PostgreSQL**.

Подключение к базе данных осуществляется через переменные окружения:

```env id="z6v2bd"
DATABASE_URL=your_neon_database_url
```

База данных отвечает за хранение основных данных приложения:

* Товары
* Букеты
* Заказы
* Клиенты
* Административные данные

Клиентская часть приложения не подключается к базе данных напрямую.

Все операции с базой проходят через серверную часть приложения.

```text id="w0u6f8"
Клиент
   ↓
TanStack Start
   ↓
Nitro
   ↓
Server Functions / API
   ↓
Neon PostgreSQL
```

## n8n

**n8n** используется как отдельный слой автоматизации и интеграций.

Он позволяет выносить внешние процессы из основного приложения и связывать LUNA FLOWERS с различными сервисами.

Через n8n могут реализовываться:

* Webhook-интеграции
* Telegram
* Email
* CRM
* Внешние API
* Автоматические уведомления
* Обработка заказов
* Уведомления администратора
* Другие бизнес-автоматизации

Основной принцип взаимодействия:

```text id="xk7v3a"
LUNA FLOWERS
      ↓
Webhook
      ↓
n8n
      ↓
Внешний сервис
```

При этом бизнес-логика самого сайта остаётся внутри приложения, а n8n отвечает преимущественно за интеграции и автоматизированные процессы.

## Переменные окружения

Создайте файл `.env` и добавьте необходимые переменные окружения.

Минимальная конфигурация:

```env id="s2e8ka"

```

По мере подключения дополнительных сервисов в `.env` будут добавляться соответствующие API keys и credentials.

Секретные ключи не должны храниться непосредственно в исходном коде или публиковаться в GitHub.

## Деплой

Проект рассчитан на современный Node.js-compatible hosting с поддержкой **TanStack Start / Nitro**.

Деплой выполняется через GitHub-based workflow.

Перед production-деплоем необходимо проверить:

* Production environment variables
* Подключение Neon PostgreSQL
* Работу SSR
* Работу API
* Работу Webhook
* Работу n8n-интеграций
* SEO
* Sitemap
* Производительность
* Корректность заказов

## Безопасность

Основные принципы:

* Секретные ключи хранятся в environment variables.
* Клиент не имеет прямого доступа к базе данных.
* Сервер отвечает за работу с приватными данными.
* Webhook endpoints должны иметь защиту от несанкционированных запросов.
* API credentials не должны попадать в GitHub.
* Production credentials должны отличаться от development credentials.
